# Reproduce and verify

The core task tests use Python stdlib plus the repository's historical tokenizer
asset tests. New training/evaluation used WSL Python with torch2.15.0+cpu and
numpy2.5.4 in an isolated package directory. See installation reports and
wsl_environment.json; that local absolute package path is not portable.
CPU installation follows the [official PyTorch guide](https://pytorch.org/get-started/locally/).

Large JSONL files are uploaded as lossless gzip. From the repository root restore
them with `python -B tools/restore_semantic_artifacts.py`; the helper verifies both
compressed and original SHA256, rejects mismatched existing files and writes only
inside this archived run. Installed dependencies and large LLM weights are not
part of the upload. Small learned checkpoints, including optimizer state, are.

Core new tests:

```sh
cd code
python -B -m unittest discover -s tests -p 'test_receipt_tasks.py' -v
python -B -m unittest discover -s tests -p 'test_ordering_receipt_tasks.py' -v
python -B -m unittest discover -s tests -p 'test_native_result_tasks.py' -v
```

For full historical regression, also restore the tokenizer assets using the root
README instructions. All 173 tests passed on the recorded Windows environment.

To repeat training, copy this run's Python scripts, protocol Markdown and dataset
directory into a NEW sibling under artifacts (do not copy models/evaluation output
directories). Keep the pinned source directories available; world records refer
to their repository-relative paths. Prepare a private CPU torch/numpy environment
and write its package path to the new run's wsl_environment.json. Run
train_safety_v5.py in WSL, then evaluate_fast_v5.py and evaluate_native.py. The
scripts intentionally reject an existing plan/output to avoid overwriting a
frozen run. Do not rerun setup or analysis into this historical archive.

To reproduce data, receipt_dataset.py builds the original fixed splits;
build_balanced.py generates the 128 factorial cells with paired histories and
four replicates, and build_safety.py restores immediate CI preferences.
Their per-worker argument lists are recorded in *_jobs.json. Native output
worlds are generated by build_native_output.py and native_jobs.json.

V2/V3, V4 and V5 intentionally use different frozen data/budget protocols. Do not
report their differences as a single-factor controlled comparison. `ci_only`
means non-Planner supervision; see REPORT.md. Native-output preparation executes
source reads/computation before the two learned disclosure decisions.
