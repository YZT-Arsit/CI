# 自主修复与 GPU 前关系学习验证

本轮：2026-11-15 晚间，Windows + WSL、纯 CPU；沿用 main。研究目标与原 Proposal 保持不变，原论文、旧实验及负面结果没有覆盖。

**结论：任务层面的“无成本、无截止时间的未来价值差异”已有条件性证明；结构化策略在有限关系分布中确实利用了关系，但完整关系泛化门槛未通过。纯 token 策略仍失败。当前不放行 GPU 大批量训练。** 这不是停止研究方向，而是把问题从不可信标签/执行旁路，收敛到了可复现的组合泛化与安全—效用学习失败。

## 1. 本轮修复了什么

1. 新增独立的、成本恒为 0 且没有截止时间的任务环境。实际读取有权限的源数据、投递消息、消费消息并计算 Meeting / Query 结果；缺失输入不能从全局答案补回。
2. 修复关系闭包：使用集合与传递可达关系，支持分叉，不用会覆盖重复键的字典代表关系。
3. 明确访问边界：控制器可见的绑定关系不等于外部接收者 R 已知。把绑定先交给 R，会把原本的未来风险变成立即违规，已有反例测试。
4. 修复 token 输入：候选动作共享同一符号字典；训练时每对样本共享随机双射，并打乱关系事实顺序。实体嵌入保持固定，测试另外使用从未训练过的嵌入行。
5. 发现并修复早期数据中链长与规则变量的相关性，建立因素交叉平衡的 V4 数据；进一步恢复被“必须有安全成功见证”过滤器误删的即时 CI 偏好，形成 V5。
6. 原始源实例 06–09 含 meeting_ordering，旧计算适配器不支持。新增独立适配器后，8 个预先选定的新 Meeting 实例均与原始任务 oracle 一致。没有改写旧适配器或原始数据。

这些修复对应独立版本。V2、V3、V4、V5 的模型与结果全部保留；没有只保留最好种子。

## 2. 价值差异的证明，以及它的边界

设 R 已收到 H=(key, sensitive_value)。一个当前合法动作发送 I=(subject, ticket)，尚未形成禁止关系。如果未来任务成功必须交付 L=(ticket → key)，那么：

- 与 H 相连的分支：任何成功终局都形成禁止关系；合规停止可以做到，但合规成功做不到，最佳严格价值为 `(CI=1, success=0, cost=0)`。
- 与 H 不相连的分支：存在实际读取、投递、计算并发布的安全成功轨迹，价值为 `(1,1,0)`。

这是在明确访问权限、单调知识闭包和输出合同下的证明。等待或换计算者不能删除已交付知识；任意增加这类操作也不改变结果。删除强制关联要求、允许该关系、历史不交付或历史不相关，差异都会消失。独立路径推导与全部 1,024 个平衡世界的实际枚举结果一致。有限枚举之外的等待/计算路由操作按语义不变的自环处理；没有声称覆盖现实中所有可能的任务改写。

第一版证明使用了**新增的合成凭据义务**，不能据此声称原始基准本来就有这个要求。因此又增加了更强的独立对照：只要求原始完整排程/查询结果，不增加任何 ticket/link 输出字段。实际结果先在内部通过消息计算并投递，再做当前合法的身份/行键披露；随后原生结果中的会议—房间或公司—城市字段完成关联。这里只需两个模型决策，前一环境需要三个。

该原生输出对照：10 个计算来源中 8 个适用，形成 64 对历史反转世界；另两个预定源实例只有一个原生结果行，不满足两种行键候选的构造条件，明确记录为不适用，没有换样本。所有适用世界的两种初始动作都立即合法，最佳未来价值发生反转；最终发布体只有原生结果。

**仍然是合成的部分：** 初始身份/行键披露选项、R 的先验历史、派生关系的保密规范。原生输出对照的准备阶段由脚本实际执行源读取与计算，模型负责之后的两次披露决策；它不是完整原生基准的自主代理复现，也不证明模型预测了尚未计算的任务答案。可信流依赖受控执行器的权限、收据与哈希账本，并非已部署的网络签名/远程认证系统。

实际参数量包含固定实体嵌入行。图策略拥有结构化实体一致性与邻接关系，这是架构提供的能力；不能把它宣传成从自然语言中学会实体绑定。token 策略只接收序列化类型三元组，无邻接矩阵/闭包/风险标签，但也不是预训练 LLM。

生成器种子也做了独立审计：平衡训练曾与旧源留出的合成种子范围重叠，虽然 world_id 后缀不同。测试结果打开前，V4/V5 的源留出改用独立种子 320000..320063；相同八个原始源实例不变。旧留出及该缺陷记录保留。V2/V3 使用的旧留出与其训练种子不重叠。

## 4. 学习结果：必须同时看安全与成功

下表按种子 17 / 29 / 41 列出。所有决策均直接取模型分数 argmax，没有规则替换、风险屏蔽、oracle 动作掩码或安全网关。

|V5 测试|图 combined|token combined|
|---|---|---|
|基础安全成功 /128|128 / 128 / 128|0 / 0 / 0|
|历史反转两侧都安全成功 /128 对|128 / 128 / 128|0 / 0 / 0|
|仅更换符号，安全成功 /128|128 / 128 / 128|0 / 0 / 0|
|链长从训练 1–2 增至 3，安全成功 /64|64 / 64 / 0|0 / 0 / 0|
|更多无关历史，安全成功 /64|64 / 64 / 64|0 / 0 / 0|
|增加关系分叉，安全成功 /64|64 / 64 / 64|0 / 0 / 0|
|八个新原始任务，安全成功 /64|64 / 64 / 48|0 / 0 / 0|
|较长链下允许省略绑定，安全成功 /64|34 / 64 / 34|64 / 64 / 64|
|两条路均不能安全完成，CI 合规 /32|0 / 0 / 0|32 / 32 / 32|
|原生输出迁移，基础安全成功 /64|64 / 64 / 64|0 / 0 / 0|

图模型在基础配对上会随一个历史关系键的改变翻转动作，并完成任务；其输入没有可记忆的实体 ID，删除关系边后配对成功降为 0，打乱标签后也没有对应收益。这支持**有限分布内的结构关系使用**，不支持无条件的关系推理泛化。

更长链的失败不能省略：种子 41 的 Planner 在长度 3 上失效；三种子对长度 3 的危险 Worker 状态也缺乏稳健安全行为。结果打开后的冻结模型诊断进一步定位了这个边界；诊断使用 oracle 构造中间状态，明确不计为自主策略成功，不用于训练或调参。第一版小诊断的候选位置不平衡，首次平衡尝试又误改了干扰历史行；最终版本按真实关联键定位，并断言四个唯一 Planner 比较。所有构造失败保留，仅 final 诊断用于解释，不能把偶然命中解释为深链能力。

token 模型的负结果尤其重要。V4 普通单侧准确率约一半，但配对两侧成功仅 0–2/128，已经暴露符号/关系判断失败。V5 加强安全监督后，三个种子在基础任务分别产生：82 次停止+46 次删减、4 次停止+124 次删减、128 次停止。它们保持了 CI，却把任务成功降到 0。**安全分数提高不是学会关系的证据。** 全新实体嵌入行测试同样没有通过。

`ci_only` 是历史代码标识，实际含义是“不含 Planner 未来监督的 Source/Worker 监督”，其中也有任务效用标签，不是纯 CI loss。V5 此对照基础成功为 128/128/64，说明部分能力可以从下游监督迁移；不能宣称未来监督是基础任务收益的唯一原因。各臂更新预算在同架构、同版本内相同；版本间同时变化的数据、批配比和步数不能当单因素消融。future_only 缺少 Source/Worker 基础监督，只作诊断。

所有版本、条件及种子详见 [all_results.csv](all_results.csv)、[results_summary.json](results_summary.json) 与各 evaluation seal。局部成功没有替换预先设置的“每个条件、每个种子至少 95%”门槛；69 个检查点均未通过完整门槛。

## 5. 实验可信度与运行限制

- 检查点全部固定后统一打开主结果。V3、V4、V5 的修复来自训练损失、代码和数据审计，未读主测试预测；新增原生输出协议也在打开预测前写下。属于本地预先冻结，不是对外注册的研究。
- 最终 V5 主轨迹与原生输出轨迹做独立重放，核验 observation 哈希、argmax、审计结果、最终状态与任务真值。最初 58 个重放任务因 Python tuple 与 JSON list 的表示差异失败；规范化比较后仅重跑这些任务，原失败记录保留。没有改模型结果。
- 源输入缓存只复用核验过的不可变输入。10 组缓存审计覆盖两种原始计算和八个新源，缓存与新加载的所有枚举终局逐字节一致；不是缓存策略动作或答案替换执行。
- 早期 worker 的广域源码检查曾因同时开发独立策略文件而记录 `source_hashes_unchanged=false`，没有将其改成通过。本轮最终逐版本核验了训练计划绑定的具体源码与 69 个检查点哈希；完整平衡数据另有独立语义审计，不能把局部核验解释为开发期间整个仓库从未改变。
- 训练总计 109,800 次小模型更新；每个已完成训练块的计算计时最长 0.566 秒。工作块设置 9.5 秒 watchdog；依赖安装、加载和整个父进程不是单次实验。初期环境负载造成 22 次数据 worker 超时、一次 Windows 训练块超时，终止开销曾使墙钟略超 9.5 秒；这些失败没有删除。恢复使用原固定 world IDs，没有重抽有利样本。
- 容量测试显式拒绝超限输入，没有静默截断：图表示最多 40 节点，token 表示最多 64 个实体及 192 tokens，图传播固定 6 轮。训练链长 1–2、主要外推到 3；这远不足以支持真实长历史部署。
- 当前数据合同、权限与 CI 语法可审计，但没有独立人工规范确认，也没有真实预训练 LLM 的训练收益、自然语言泛化或论文新颖性证据。

## 6. 当前决策和下一步

**GPU / 大批量实验：NO-GO。** 可以继续使用本轮代码、数据与反例做 CPU 机制实验；不应把更大的模型、更多训练步数当作尚未验证的关系学习的替代证明。

下一步应固定全新验证协议，分别处理：

1. token 模型的身份绑定与一跳/多跳组合能力，先测清是否真的可学习，再考虑课程或结构归纳偏置；不得用显式闭包伪装为学会推理。
2. 下游即时安全在不同链长上的一致性，防止“会提前选路，却不会在坏状态安全停止”；保持安全与效用双指标。
3. 独立来源支持的接收者知识与 CI 规范；原生任务输出已能承载机制，但合成历史/规范不能自动升级为外部真实性证据。
4. 通过新的配对、符号、组合和无解状态门槛之后，再讨论小规模真实 LLM 训练。大规模训练还需单独验证长上下文、截断、批处理与数值路径。

本轮已实际修复和训练，而不是把修复工作退回给用户。没有完成的证明也明确留下：**目前不能诚实地宣称，目标文本模型已经学会稳健的关系规律。**
