# Native-output dependency control, before opening policy results

The synthetic mandatory-receipt contract proves only a conditional mechanism.
Add a stronger separate control: require ONLY the original complete native
Meeting schedule or Query result. Its actual row fields create the final join;
no ticket binding or extra disclosure is appended as a task requirement.

Computation and source deliveries occur first. The actual computed native result
is delivered to Planner/Worker; future edge metadata is parsed from that receipt,
never from the evaluator's expected answer. Planner then chooses one initial
identity/row-key delivery, both presently legal, before Worker publishes the native
result (or redacts/withholds and fails the original result requirement). There are
TWO learned decisions, rather than the receipt task's three. This changes process
length without creating labels from length. Original source computation remains
necessary and actual received evidence is consumed.

Identity/row-key alternatives, recipient's prior row-value/secret relation and
the forbidden derived relation remain SYNTHETIC. This is not independent native
privacy norm validation. The decision is after internal computation, before
external publication: do not claim unseen future task outputs were inferred.

Use both original computation sources and all eight fixed new Meeting sources;
report any source lacking two distinct native row values. Fixed seeds420000+,
eight worlds per qualified source, matched history-key swaps. Evaluate every V5
model unassisted, frozen, no new training. This is an additional source-output
mechanism diagnostic, not a replacement or relaxed primary gate.
