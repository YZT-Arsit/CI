# Repeated small-set query-only versus joint fitting

After contrast sampling restored base tasks but increased violations, the final mixed model still failed changing queries on its actual TRAIN prompts. Test the hypothesis that the shared actor loss impedes query fitting. This is an ablation diagnostic, not a proposed final query-only method or a claim of gradient conflict.

Select the first forced TRAIN batch in each role x depth1/2/3 x Meeting/Query cell from the preserved contrast-repair schedule, without filtering by model output: 18 pairs total. Use each batch's original two views and all candidates. Repeat eight epochs with the fixed seed59117 shuffle:144updates in each trained arm. Both arms start from the identical final contrast-repair/mixed_depth weights, fresh AdamW, seed17, lr0.0002, weight_decay0, clip1, CPUFP32 and4threads. No separate fallback updates, new data or early stopping. Save only final adapters.

Both arms execute the unchanged teacher_binding::loss_for_views forward code with teacher=True and weight0. The joint arm backpropagates its returned total; query_only backpropagates its returned query_loss. This keeps queries, actor inputs, sampled tied targets and forward RNG use identical while removing actor gradients from one arm. Shared weights are still mutable; this does not freeze an actor branch. Gradient norms/clipping and optimizer trajectories can differ as consequences of the loss change. Log both losses and token exposure, even when the actor loss is not optimized.
