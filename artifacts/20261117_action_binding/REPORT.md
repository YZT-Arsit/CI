# 关系判断如何进入行动：CPU 修复与审计报告

研究目标不变：共享语言模型根据可信信息流和任务依赖，自主选择安全且能完成任务的行动。**本轮建立了有限的一跳因果证据，尚未证明多跳关系泛化、长程 Agent 协作或真实规范的跨任务有效性。大批量 GPU 实验仍为 NO_GO。**

通俗方案见 [SOLUTION.md](SOLUTION.md)，复核入口见 [REPRODUCE.md](REPRODUCE.md)。本轮所有模型学习均为 SmolLM2-135M-Instruct 的 CPU FP32 LoRA、单个随机种子 17。开发集结果用于诊断和改进，不是独立最终测试；多个检查点不等于多个种子。

## 1. 解决了哪一部分

以前把“关系判断是否正确”和“是否利用这个判断行动”混在一起。冻结诊断发现：给旧 trace17、balanced17 检查点正确的证明前缀时，二者均达到 12/12 配对正确；无证明、但仍强制 ANSWER 前缀的动作词元读出均为 0/12。只交换路径文本就会全部变错，交换 TASK 真值位却不改变答案。这是提供答案线索后的读出能力，不能算自主关系推理。

先独立训练每个候选动作的合规完成查询，可以达到一跳 16/16 候选—历史配对正确；两跳为 0/16，三跳为 0/16。添加配对分数差损失也没有可靠解决组合问题。继续只训练动作又会把查询回答变成动作字母，说明查询接口被遗忘；这不等于证明内部关系表示全部消失。

实际修复采用同一组权重联合学习查询和动作，并将**模型自己预测的判断**交给它自己的行动阶段。没有真值判断进入行动输入，也没有图算法替模型选动作。推理是同一模型的多次调用，不能计作多 Agent 协作。

在该模型的一跳、新名称开发对上，冻结输入与权重，只干预它自己产生的判断：

| 判断通道 | 配对路线均正确 | 含义 |
|---|---:|---|
| 原始自预测 | 8/8 | 模型能利用自己的判断 |
| 原样重复 | 8/8 | 恒等控制一致 |
| 加无关标记 | 8/8 | 该扰动不改变结果 |
| 交换两个候选的自预测 | 0/8，双侧都错 | 16 个状态都发生有效内容变化，动作随之改变 |
| 擦除判断 | 0/8 | 该条件下退化为固定选择 |

这是**自生成文本通道对行动的有限因果作用**，不是隐藏激活的 IIT 验证，也不是一般图推理证明。更深层样例往往两个候选都被预测为相同值，交换是无效干预；已分别报告有效分母，未把它们算作模型不敏感的证据。该模型一跳完整回合配对成功仍只有 5/8，不能把路线正确当作安全执行成功。

一跳换名字成功仍可能来自局部关系匹配，不能替代组合规律的证明。这里的事实可信性由受控环境合同与执行器提供；没有证明语言模型能在真实系统中识别伪造来源或核验来源权限。因而用户要求的完整“可信信息流与任务依赖导致价值差异、模型学到关系规律”门槛仍未整体通过。

最终又冻结类别平衡检查点，新增 16 对世界，每个世界用两套新名称和显示顺序呈现，先封存响应再评分。两套呈现的路线配对正确分别为 **16/16、12/16**；32 个语义状态中有 28 个在两套呈现下均正确，另 4 个受到呈现变化影响。128 次查询中 123 次正确；59 次有效判断交换全部改变了合法动作，64 次恒等控制原始输出完全相同。所有查询提示均为 206 词元，动作提示均为 218 词元，因此该对照不存在提示长度差异。**这加强了判断通道被使用的证据，也留下了符号／顺序敏感的明确反例。** 两套呈现共享同一批 16 对世界，不能当作 32 对独立任务；此项只评 Planner，不是完整执行。见 [封存后评分](alias_confirmation/RESULTS.json)。

## 2. 安全—效用修复

发现两个可修复问题：

1. 过去过滤掉“所有动作价值相同”的状态，连必要查询监督也删掉了。现在保留全部查询标签；动作损失接受所有等价最优动作，不编造唯一偏好。训练池重新纳入此前排除的 416 个状态，不意味着这 416 个状态都在本次短训练中被采样。
2. Worker 候选中负例多，容易学成一律回答“不可完成”。在相同初始化、批次、更新次数和优化器下，比较普通查询损失与批内正负类等权损失。

| 200 次更新后的完整回合配对成功 | 一跳 | 两跳 | 三跳 |
|---|---:|---:|---:|
| 补齐覆盖，普通查询损失 | 2/8 | 0/8 | 0/8 |
| 补齐覆盖，批内类别平衡 | 8/8 | 2/8 | 0/8 |

这是新开发样例上的正信号，但**安全仍未解决**：类别平衡组在所有路线不可合规完成时，仅 2/8 回合保持 CI；在可选披露条件中也只有 6/8 保持 CI。授权与草稿条件各自均为 7/8 完成、8/8 保持 CI。不能只选择一跳 8/8 报喜。

后续匹配试验在同一类别平衡检查点上，仅改变即时安全损失权重。损失提高合法选项中安全动作的概率，运行时仍由模型自由生成，不加动作屏蔽。其非恒定监督只有 32/200 个训练状态，全部为 Worker；它不会直接教会 Planner 的远期关系推断。零权重损失及梯度与既有实现逐项完全相同，安全梯度方向和全安全集合的零损失已通过数值检查。最终结果见本报告末尾的完成结果表。

进一步核查这 32 个状态：24 个的安全集合恰好等于原有最优动作集合，主要作用是强化已有选择；另 8 个的安全集合更宽，会接受安全但效用更低的动作。因此这个试验检验的是安全监督权重，而不是新增关系知识或新方法创新；必须同时看任务完成率。[日程核查](RISK_SCHEDULE_AUDIT.json) 保留具体计数。

实际结果为混合／负面：安全损失组一跳完整配对成功 4/8，对照 1/8；但无可行路线时，保持 CI 为 3/8，对照 5/8。两组的两跳、三跳配对成功均为 0/8，授权与草稿各自都是 4/8 完成。**只增加这个安全损失不足以解决问题，不能作为已有效的安全修复推广。**

普通继续训练组有 7/226 次动作输出不符合格式，安全损失组有 1/238 次，均非超时。严格解析与评分保持不变，未把裸字母或 `A = A` 事后重新算成成功。由于这个新 DEV 与此前 8/8 的 DEV 不同，且没有在相同新 DEV 上评测未更新检查点，不能把跨轮分数差单独归因于继续训练。格式失败本身仍是部署缺口。见 [格式归因](risk_repair/FORMAT_AUDIT.json)。

## 3. 关系泛化怎样检验

已把“换名字成功”和“会关系组合”分开。新名字来自与训练不相交的实体词表；选项、事实、边的显示顺序随机化。内部边反转控制保留首尾连接、实体集合和历史，旧模型在深度 3/4/6 上均失败。这排除了只靠端点记忆就能通过的弱评测，但反转还留下局部度数线索。

进一步构造两个等长环、相同节点度数和组件大小的控制，并改变历史锚点属于哪一组件。第一版发现单边闭合捷径后已废弃为成功证据；第二版消除了该捷径。其原始边列表仍有组件排序线索，所以模型只能读取已随机打乱的呈现；该家族还可用无向连通性判断，不能直接声称学会一般有向可达性。

新的组合课程对照使用相同 32 个基础组、相同重复次数和角色日程：一组单跳，另一组两跳/三跳；四跳、六跳、内部反向边和环结构只作开发测试。原始方案的 16 对 32 组混杂在训练前被审计发现，已取消并保留记录。不同深度改变了生成器的随机数消耗，因此相同种子不等于只改一条边的精确反事实；两组词元预算也不同。

完成后的配对完整成功：单跳课程在深度 1/2/3 上为 4/4、1/4、0/4；混合深度课程为 4/4、3/4、1/4。两组在四跳、六跳、内部反向边、两种环结构上全部为 0/4，Planner 配对正确数也为零。补充多跳数据在训练深度附近有局部收益，尚未证明可外推的组合规律。该审计重放 160 个回合、467 次决策、1,081 次查询，独立核查 400 个状态，记录与评分错误为零。

## 4. 32 跳不是 32 步协作

重新核验旧结果：192 个深度 32 回合都只有 3 次策略决策、3 次环境转换。这个命名混淆已经纠正；没有通过增加空操作来凑足 32 步。

已接入固定版本的 [原版 τ²-bench 电信环境](https://github.com/sierra-research/tau2-bench/tree/37199f36924c8896f5e048360691f8476cd89ba1)，29 个选取文件逐字节匹配官方 Git blob，保留 MIT 许可。114/114 个标注动作计划通过原生状态断言；共完成 744 次原顺序、逐动作删除和顺序反转试验。删除 489/516 次会破坏成功，反转 29/114 次会破坏成功。最长计划有 12 次实际数据库变更调用，71 个计划包含用户和助手两侧工具。

这是**真值动作计划的原生执行与依赖诊断**，有 0 次学习策略决策、0 条 Agent 通信，不是论文 Agent 分数、完整规范合规性或 32 步协作证据。下一步必须连接角色局部观察和真实消息，并分别统计决策、通信、工具调用和状态变化。详见 [执行报告](TAU2_EXECUTION_REPORT.md)。

## 5. 数据集采用混合方案

| 数据 | 本轮用途 | 可以支持 / 不能支持 |
|---|---|---|
| 自建关系配对与组合训练 | 隔离关系、授权和任务条件；产生可执行标签 | 支持受控机制诊断；不能自动代表现实规范 |
| 内部边控制 48 个世界、环控制 V2 32 个世界 | 排查端点、局部度数等捷径 | 仍须保留已披露的结构家族限制 |
| 组合 V2：128 个世界版本、640 个状态版本 | 相同基础组的一跳对两/三跳训练 | 仅两个底层任务源实例，不是来源留出泛化 |
| τ²-bench 原生 114 项任务 | 外部后端执行和依赖审计 | 真值计划重放，尚未训练或评测自主协作 |
| GitLab 官方规范 28 个条款案例 | 真实条款的条件、例外与未知信息 | 条款级 DEV，不是完整业务流程或跨组织迁移 |

GitLab 手册固定到官方版本 `e1c706abbe174add18ac09a72976df2a79d0178c`，记录来源与内容哈希。对初始 24 个案例隐藏预设标签后审查，发现 2 个例外条件没有明确要求的 ZenDesk 记录位置；这两个输入保持不变并标成 UNKNOWN，另补 4 个明确位置的对照。最终为 PASS 4、FAIL 12、UNKNOWN 12。

只有一名独立模型审查者，尚无人类审核或执行验证，全部是开发数据，不具备动作策略训练资格。不能把 GitLab 的组织规定直接套进虚构电信组织。来源适用范围和例外必须保留；缺少事实时保持 UNKNOWN。详见 [来源登记](NORM_SOURCE_REGISTER.md) 和 [数据资格](policy_cases_v2/QUALIFICATION.json)。

## 6. 交付与 GPU 门槛

已有 187 项代码回归通过，包含 7 项新增配对指标测试；原始输出、独立重放、标签核查、权重与输入哈希均保留。审计零错误只说明记录和评分一致，不表示研究假设成立。另有 Qwen2.5-7B Q4_K_M CPU 零样本小探针，三个关系条件均为 0/2 配对正确；它与训练过的 135M 不是匹配比较，不能据此归因于模型规模。

169 个 JSONL 原始文件共 17,959,960 字节，无损压缩为 1,575,119 字节；已在新隔离目录全部还原并核验哈希，重复运行不改文件，遇到不同的现存证据会拒绝覆盖。12 个新增 LoRA 检查点与负结果一并保留，基础模型和依赖缓存不上传。逐文件清单是运行后的完整性记录，不冒充实验前封存。机器可读结论见 [readiness.json](readiness.json)。

进入大批量实验前，仍需同时满足：

- 在预先固定的新测试集上，用至少三个训练种子重复关系通道结果，并保留安全与完成率。
- 在新结构、内部边控制和来源留出任务上，通过多跳配对联合成功，而非仅名称替换。
- 在无可行路径、授权、可选披露和草稿等条件中，证明安全提升没有靠全面拒绝换取。
- 在真实多角色执行中证明消息与任务依赖，不能用图深度代替协作步数。
- 对自然规范完成独立适用性核查、未知事实处理和跨任务验证。

本轮没有据此放行 GPU，也没有宣称新方法优势已经成立。可继续做有边界的 CPU 修复；下一轮优先依据组合课程与即时安全对照的具体失败位置安排实验。
