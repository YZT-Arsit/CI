# 从短 CPU 试验到大规模训练：已测因素与缺口

本轮不声称已模拟所有规模因素。优先测试会让小规模正结果失真的因素；没有 GPU 的部分保持未验证。

| 因素 | 已完成的短试验或审计 | 结论 / 后续要求 |
|---|---|---|
| 关系查询与行动接口相互干扰 | 查询预热后只训练动作，再测试原查询 | 出现输出接口遗忘；联合保留查询监督 |
| 查询正负类不平衡 | 同批次普通损失对批内正负等权 | 一跳改善，但违规仍存在；不凭总体准确率决定放行 |
| 相同价值状态被过滤 | 重新纳入 416 个训练池状态 | 保留查询学习，动作允许全部等价最优；不是虚构偏好 |
| 角色曝光不均 | 审计 Planner/Source/Worker 更新数 | 早期 Planner 只有 8 组；后续固定角色日程 |
| 训练课程混杂 | 先发现 16 对 32 组差异，取消后改成同 32 组 | 仍需披露深度改变的词元预算和随机数消耗 |
| 优化器状态 | 早期预热对照有重置不对称；后续两组都重置 | 早期仅比较完整方案，不单独归因知识预热 |
| 人工证明与标签泄漏 | 冻结前缀干预、未来标签 logits 不变、预测判断输入重建 | 教师前缀只作诊断；行为评测使用自身判断 |
| 固定名称、选项顺序和局部捷径 | 不相交实体词表、随机化呈现、内部反边、等度双环、额外双呈现复核 | 每种结构仍注明残留捷径；短路径成功不等于一般关系组合 |
| 安全与效用互相挤压 | 分别计 CI、完整完成、无解和授权等条件；安全损失匹配对照 | 任一可解条件全面拒绝，或无解条件违规，都阻止放行 |
| 分母与无效输出 | 配对两侧都正确、有效内容干预、独立重放 | 两个无效输出不算一致；无内容变化的交换不算有效干预 |
| 数据集来源泄漏 | 明示两个底层任务源，真实来源与合成世界分开 | 仍需来源级划分；新的随机世界不是新任务源 |
| 单步时限和资源 | 每次更新 9.5 秒监测，CPU FP32，串行模型作业 | 加载与评测不在更新计时内；总耗时单列，未跑 GPU |
| 混合精度、分布式归约与大批量 | 本轮未测试 | GPU 上先做短数值一致性、梯度有限性、显存与批量检查；不能由 FP32 CPU 结果推定通过 |
| 长上下文和 32 步真实协作 | 审计 32 跳实际只有 3 决策；接入原生外部后端 | 仍需角色局部信息、真实消息干预和长期信用分配；不靠插入空步骤达标 |
| 统计稳定性 | 全部本轮训练为 seed17 开发诊断 | 固定方案后至少三种子，并使用封存新测试；现有迭代 DEV 不能改名最终测试 |

已有测试回答的是“哪里断了、哪项局部修复值得继续”，并未消除以上所有缺口。进入大批量实验前先通过 [报告中的门槛](REPORT.md#6-交付与-gpu-门槛)。
