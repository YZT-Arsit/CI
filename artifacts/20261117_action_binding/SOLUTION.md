# 这轮修复在解决什么

目标仍是让共享语言模型根据可信的信息流和任务依赖，自主选择既安全又能完成任务的动作。本轮是 CPU 机制与数据修复，不是最终 KCI-DPO 收益验证。

目前的问题可以拆成三个环节：模型能否判断关系；这个判断是否真的影响动作；后续角色是否还能把任务安全做完。把它们混成一个总分，会掩盖“路线选对但最后拒绝完成”与“路线本身选错”的区别。

当前实现让**同一组模型权重**先独立回答每个候选动作是否仍可合规完成任务，再读取自己的判断来选择动作。训练时保留关系查询监督，防止只训练动作后把查询接口遗忘。推理时没有正确标签输入，没有图判决器代替模型选动作；未知或格式错误的预测会如实记录。

```mermaid
flowchart LR
    O[经过环境核验的可见事实与任务合同] --> Q[语言模型：逐候选独立判断]
    Q --> E[模型自己的判断]
    E --> A[同一语言模型：选择动作]
    O --> A
    A --> X[原生环境执行]
    X --> V[分别计安全与完成]
```

这条连接已出现有限正证据：在单跳、新实体名称的 8 对案例上，在自预测判断条件下得到 8/8 配对路线正确；交换判断后变成 0/8，且双侧都错；恒等输入与无关标记不改变结果。这里没有注入真值判断。这证明了本组样例中的判断通道被实际使用，**没有证明它总能算对判断，也没有证明任意多跳推理**。辅助监督对照的单跳路线同样为 8/8，因此不能把这个数值解释为显式通道的性能优势。

完整回合仍受后续执行影响：该检查点单跳配对安全完成只有 5/8。它对错误中间判断的敏感也意味着错误会传递到动作，不能把通道有效直接当作安全保证。

最终换名／换顺序确认也没有被美化：后续类别平衡检查点在同一批 16 对新世界的两套呈现中，路线配对正确分别是 16/16 和 12/16。有效交换自己的判断时，59/59 次都改变动作；但仍有 4/32 个语义状态受呈现影响。可以说“模型确实用了判断”，还不能说“已经彻底摆脱名称和顺序线索”。

接着修复了一个监督缺口：以前为了避免编造动作偏好，删掉了价值相同的动作状态。但这些状态仍有必要的关系查询标签，例如“已经授权，因此两条路线都可行”。新的训练保留这些查询；动作目标同时接受全部等价最优动作，不强行规定其中一个更好。另设匹配对照，只改变批内正负查询损失权重，检验 Worker 总回答“不可完成”的问题。

这一修复在新开发集上的单跳完整配对成功从 2/8 到 8/8，但无解条件的安全性仍差。随后增加即时安全损失的匹配对照也没有解决它：单跳配对成功 4/8 对 1/8，而无解时保持 CI 只有 3/8 对 5/8。因此目前有效的是部分监督和判断通道修复；安全—效用的整体解法尚未验证成功，不能直接扩大训练量。

关系泛化继续用独立对照检验：同样的初始权重、相同 32 个基础场景和采样次数，一组继续单跳训练，另一组接入两跳/三跳。四跳、六跳、内部反向边和锚点连通性留作开发测试。原本 16 对 32 组的数据量混杂在训练开始前被审计发现并修正，原计划保留而未训练。

这个对照已经完成：两跳完整配对成功从 1/4 到 3/4，三跳从 0/4 到 1/4；但四跳、六跳和结构控制均为 0/4。它支持继续改进组合监督，不能声称已经学会可泛化的关系算法。

数据采用混合方案：

- **自建配对数据**用于只改关系、授权或任务条件，检查模型是否依赖固定名称、边顺序、端点或局部图形线索。它适合机制诊断，不能自行证明现实规范有效。
- **外部原生任务环境**采用固定版本 τ²-bench。114 个真值动作计划已能在原生后端执行，删除动作和反转顺序会破坏部分结果。最长是 12 次有状态变化的工具调用；这不是 32 步模型协作成绩。
- **真实组织规范**取自固定版本 GitLab 官方手册。28 个条款级案例经过隐藏预设标签的模型审查，其中 12 个保持 UNKNOWN。它们尚未执行为完整业务任务；模型审查也不是人工或组织官方认可，不能直接接入二元动作标签训练。

因此目前不能批准大批量 GPU 实验。完整门槛还包括三种子稳定性、多跳与新结构上的安全—效用联合成功、真实多角色消息依赖，以及规范适用范围和跨任务验证。具体数值及最新运行状态见 [PROGRESS.md](PROGRESS.md)；所有失败、审计发现和被替换的实验设计均保留。
