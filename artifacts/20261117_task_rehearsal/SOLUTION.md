# 关系知识如何进入行动：本轮修复及边界

研究目标保持 [Proposal v0.6](../../docs/KCI_Align_Research_Proposal.md) 不变：模型根据可信交付历史、接收者知识、权限和任务依赖，自主选择安全且有用的行动。

## 当前证据把问题分成了两段

第一段是“读懂关系，判断某行动之后还能不能合规完成任务”；第二段是“根据判断选择行动”。之前的输入干预已经表明：在固定事实和选项的条件下，翻转提供给模型的判断，144对中有139对动作随之改变。但那些判断由实验者注入，所以它证明输入通道有效，尚未证明模型能自己可靠地产生关系判断。详情见[输入通道实验](../20261117_join_policy_transfer/REPORT.md)。

局部图关系训练提供了第一段所需的一部分能力，然而“能答一轮图扩展题”和“能回答原任务中的全局CI问题”仍有距离。先前训练保留了Worker行动重放，却没有同时重放原任务的全局关系问题。本轮只检验补回这类监督是否有用；不预先把全部失败归因于遗忘。

## 本轮具体做法

两个模型从完全相同的参数出发。每次都练四道局部关系题、四道Worker行动题；另外四道题分别是“更多局部关系题”或“原任务的全局判断题”。在三个不同起点重复这个配对实验，每个模型54次更新。训练后，模型必须自己回答判断题、自己选动作，环境按实际动作继续运行，评估器不会把正确答案喂回模型。

```mermaid
flowchart LR
    A[实际交付历史和任务条件] --> B[语言模型回答候选行动的全局判断]
    B --> C[自产0或1判断；无效输出解析为unknown]
    C --> D[同一语言模型选择行动]
    A --> D
    D --> E[合成环境按动作执行]
    E --> A
```

图中是实际评估路径。局部图题只参与参数训练，没有在运行时被外部程序迭代成正确答案。环境负责执行和事后评分，不能用评分答案替换模型判断。

本轮没有“完全不做局部关系训练、只训练全局任务”的独立对照。因此，global组即使进步，也只能支持补回原任务监督有帮助，不能单凭它证明局部算子被模型复用到了全局任务。

举例：接收者已经获得某人的身份关联，而某条候选计划会补齐通往受限属性的关系链。任务要求完整结果时，模型不能只学会停止；它需要选另一条仍能完成任务的合法计划。相反，如果权限明确允许这一披露，模型又不能因为看到关系链就一律拒绝。最终评分同时报告任务完成、违规、无效输出和换历史/换名称后的成对结果。

## 为什么使用自建数据，也为什么它不够

本轮训练沿用自建、可执行、可追溯的合成环境。它可以精确交换历史关系而保持长度、标签数量和行动预算受控，也可以通过环境检查监督是否正确。这是做因果对照的工具。18个原任务训练组合来自原TRAIN，覆盖三角色、三深度、两任务；反复换名并没有把18组变成大量独立业务案例。

本轮原任务评估的1跳与3跳深度都在训练中出现过。新种子生成新世界、换别名测试绑定，但这不是深度外推，也不是留出一类全新业务任务。

新增全局监督只包含未授权、必须完整结果时的Commit、Deliver和Full判断；没有新增Minimal或Stop查询监督，也没有新增授权或允许简化条件的全局训练。这些条件仍在评估中保留，用来暴露这套小型课程的覆盖缺口。不能把它称为完整的安全—效用训练集。

外部数据用于另一层验证：业务条款是否支持规范判断，真实工作流是否要求那些动作，未见任务上能否迁移。当前已有外部候选和条款探针，应继续利用有来源的材料并保留UNKNOWN。把它们未经审核地混入本轮微型训练，会同时改变数据来源、规范和任务，无法回答这次的单一修复假设。本轮没有新增外部训练样本，也没有完成外部盲测。

## 不能跳过的后续证据

1. 本轮的配对优势和局部保留必须共同成立；只提高成功率但增加违规，或只增加拒绝，都不算修复。
2. 原任务查询即使恢复，也需要单独证明它依赖正确的实际交付、权限和任务条件，并能处理未见关系组合。换名字和换种子只是其中一部分。
3. 32跳关系推断仍不等于32步协作。需要每步有实际执行后果、跨角色交付以及可核对的任务推进，不能用空消息补足步数。
4. 自然规范必须允许“不知道”。既有条款探针对信息不足情形仍失效，不能以合成奖励一致性代替这一检查。

## 文献依据与新颖性限制

重放已有任务以减轻持续学习中的遗忘属于已有方法方向。例如 [Distill and Replay for Continual Language Learning](https://aclanthology.org/2020.coling-main.318.pdf) 将经验重放与蒸馏结合；本轮没有实现其完整方法，也不把“加入重放”当作创新。[持续指令微调的实证研究](https://arxiv.org/html/2308.08747v4)报告了遗忘现象，但不能据此推断本项目所有失败都来自遗忘。

[CLUTRR](https://aclanthology.org/D19-1458/)通过留出逻辑规则组合与加入噪声事实区分关系泛化和鲁棒性。它为评价设计提供参考；它的亲属关系任务不直接验证本项目的可信交付、CI权限或任务效用。本轮没有运行CLUTRR，不能声称已通过该基准。

上述三个来源于2026-11-17通过Exa核对。当前修复是一个可证伪的工程与学习诊断。是否有效以本目录REPORT和原始结果为准，完整目标和大批量GPU门槛另行判断。
