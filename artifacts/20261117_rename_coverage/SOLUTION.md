# 这次在修什么，以及数据为什么这样建

本轮检验的是一个具体缺口：最近的小集重复训练中，同一关系始终配同两套名字，模型可能适应了这些名字，而没有形成稳定的关系判断。修复做法是让同一关系见到16套名字，同时保持标签、动作、关系图、顺序、训练次数和损失不变。它是否有效，以这次匹配实验的实际结果为准，不能因为数据设计合理就算修好了。

可以用一个简单例子理解目标。收件人已有“编号对应秘密”的信息时，发送“姓名对应编号”可能揭示秘密；如果收件人没有这条知识，同一条消息的风险可能不同。把姓名换掉不应改变判断；改变真正相关的知识或任务依赖则应该改变判断。模型还必须根据这种判断采取行动，完成能合规完成的任务，在无合规路径时安全终止。

因此我们分开检查三件事：

1. **关系判断**：同一关系换名字仍答对；只改变关键关系时，成对答案按真值翻转。
2. **判断进入行动**：给定正确判断时能选对动作，并保留既有行动能力。这是条件诊断，不等于自主成功。
3. **自主安全与效用**：模型自己判断、自己选择动作，执行器只记录结果，不替它纠错。120个有合规路径的任务呈现与8个无解呈现分别报告。

数据采取组合路线。自建数据用于严格控制反事实，逐项检验名称、顺序、长度是否成为捷径；外部真实任务与规范用于检验这些关系是否有真实业务含义、能否迁移。不能只用自建标签证明自然规范有效，也不能直接把外部任务改造成合成规则后就称为真实规范验证。本轮新增的是可控合成评估，不冒充外部验证。

新生成的任务仍属于此前开发过的任务族；第三词表只是与实验中登记的两个词表分离。I/L/H关系标记、回答格式和规范语法保持固定，所以本轮不检验关系谓词名称、指令改写或自然语言规则的泛化。两个任务家族也不足以支持跨业务的广泛结论。

如果换名判断改善但自主表现没有改善，就继续定位行动接口；如果原名拟合仍好、换名仍差，就说明这份名称增广还不够。如果两者都失败，不能仅据此断言模型容量不足。无论哪一种，都保留失败结果，不能用更多GPU训练替代尚未获得的关系学习证据。

真正32步协作也需要另外检验：当前每回合最多3个政策动作，32跳图推断与32次角色交互不是同一能力。完整目标还包括自然规范审查、外部任务迁移和长程自主协作，本轮没有完成这些部分。
