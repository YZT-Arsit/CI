# 关系判断进入行动：冻结模型交叉诊断

本轮定位到了可修复的两层问题，但尚未完成研究目标，也不支持 GPU 大批量放行。给同一个模型正确的关系判断，能显著改善行动；模型自身生成判断的可靠性和部分行动绑定仍不足。没有用规则、图模型或两个独立模型替代 Proposal v0.6 的共享执行模型。

## 做了什么

复用上一轮三个冻结语言模型检查点，不训练、不选择新任务。固定同一批 DEV 的 36 个基础组、56 个语义世界、280 个可达观察状态、560 种呈现。先封存三个模型自由生成的关系判断，再交叉输入三个行动模型，最后单独输入环境真值。交叉不同检查点仅用于诊断；只有对角线保持同一检查点完成判断和行动。

每个模型都在完全相同的状态上测试，包含两条路线后的状态，避免只比较不同模型自行走到的状态。固定行动模型与状态时，输入中只有关系判断位发生变化。模型仍自由选择动作，没有规则替换。利用完整的确定性状态策略表在原生环境中重构回合，不把这些回合算作新的在线模型调用。

## 主要结果

表中每项为严格成功回合数 / 112。每列使用同一批关系判断，每行固定行动模型。

| 行动模型 | 普通 SFT 判断 | 正确输入 SFT 判断 | 较早 SFT 判断 | 环境正确判断（oracle） |
|---|---:|---:|---:|---:|
| 普通 SFT | 38 | 35 | 60 | 97 |
| 正确输入 SFT | 46 | 39 | 69 | 104 |
| 较早 SFT 参考 | 69 | 62 | 82 | 102 |

“正确输入 SFT”指上一轮在行动训练阶段使用正确关系判断；推理时它生成的判断仍可能错。oracle 列是诊断，不是模型自学结果，也不保证是性能上界。

交换成较早模型的判断也不是有效的整体修复：正确输入 SFT 的严格成功从 39 增至 69，但合规回合从 103 降至 89；普通 SFT 对应为成功 38→60、合规 102→97。这种效用增加伴随安全退步，不能因成功率上升就放行。

对正确输入 SFT，保持模型与状态不动，把自身判断换成真值：225/560 个输入改变，97 个动作改变，修复 92 个原有动作错误，没有引入新的最优性错误；335 个完全相同的输入没有动作差异。这是**文本关系判断通道对行动的干预证据**。它不能证明内部神经表示满足因果抽象，也不能证明模型独立掌握了关系推理。

oracle 条件下，正确输入 SFT 的一跳、三跳、内部三跳、四环完整四视图组分别通过 8/8、4/4、4/4、4/4；自身判断条件下四类均为 0。oracle 的严格成功为 104/112，CI 合规为 110/112，两个不安全呈现来自同一个 `both` 世界的两种视图，因此不能称为完全安全。

全部可达状态比实际路线暴露出更多问题。Worker 在 oracle 输入下的最优动作数：普通 SFT 为 153/224，正确输入 SFT 为 178/224，较早 SFT 为 162/224。正确输入 SFT 仍有 46 个 Worker 呈现选错，不能用较好的回合分数掩盖这部分失败。Planner 与 Source 的 oracle 最优动作均为 112/112、224/224；但 Source 固定执行交付在全部 224 个状态都属于最优动作，单看这个角色的准确率不能证明关系学习。

## 训练拟合与关系泛化

在原来的 320 个训练呈现上，正确输入 SFT 使用它训练时真实见过的正确行动输入：Planner 80/80、Source 80/80、Worker 152/160。训练 Worker 仍有 8 个错误，说明行动层连训练拟合也未完全完成。普通 SFT 对相同 oracle 条件为 80/80、80/80、130/160，但它训练时使用自身预测，因此后者不等同于其原输入训练拟合。

关系判断训练拟合的补充实验在主结果评分之前登记，复用同两个冻结检查点和原训练查询输入，不新增训练或验证数据。1,600 条自由生成响应已封存并通过核验。整组候选判断全部正确的 TRAIN 呈现数：普通 SFT 为 Planner 78/80、Source 62/80、Worker 118/160；正确输入 SFT 为 78/80、60/80、119/160。正确输入 SFT 的 Source 在 68 条正例中仅判断正确 48 条；Worker 的 296 条负例中错误判断为正例 34 条。这说明不是单纯“训练已学会、测试不能泛化”：训练集本身还有明确的查询拟合不足，同时 DEV 表现进一步下降。TRAIN 与 DEV 构成不同，不能把差值解释为纯泛化效应。

DEV 中整组候选判断全部正确的状态数如下。不能把单条二分类较高的准确率等同于完整决策信息可靠。

| 模型 | Planner /112 | Source /224 | Worker /224 |
|---|---:|---:|---:|
| 普通 SFT | 60 | 127 | 139 |
| 正确输入 SFT | 67 | 128 | 140 |
| 较早 SFT | 63 | 143 | 120 |

较早模型并非所有角色上的判断都更准，却有更好的自身回合结果；因此单一平均判断准确率不足以解释安全—效用。需要同时看错误发生的位置、错误判断如何改变动作、以及全程联合成功。

## 数据集与下一步修复

本轮新增的是可审计的固定状态诊断集与原始模型输出，不是新的独立业务数据：560 个 DEV 呈现、320 个 TRAIN 呈现，保留来源、状态标识、输入、原始输出、耗时、哈希及环境标签。TRAIN/DEV 共 880 个呈现按“角色 + 可选动作 + 正确完成判断”分成 10 类，各类存在共同最优动作，未发现标签冲突。三集合两两相交而总体无交集的反例已用于核验该检查器。这只是有限支持集的一致性，不证明一般可学习性或真实规范有效性。

后续应先解决原训练输入上的查询和 Worker 拟合，再在固定的、更长关系和未见实体呈现上检验；不能用 oracle 或另一个检查点的判断作为最终系统收益。共享模型内可分别安排查询监督与行动监督的训练阶段，保留两个头绪的回放样本，并与等更新数的联合 SFT 对照。是否有梯度干扰尚未测量，不能由本次交叉表直接推断。

数据路线仍为：**自建配对干预用于证明机制，外部原生任务与规范用于检验迁移**。自然规范不能由我们自己的奖励标签自证；外部任务成功需同时核验必要工具动作与最终状态。已有外部规范探针和原生协作失败证据保留，本轮没有新增自然规范迁移或 32 步自主协作证据。

## 审计与边界

主实验 4,032 条查询、6,720 条 DEV 行动、640 条 TRAIN oracle 行动，合计 11,392 条生成响应；训练查询补充 1,600 条，总计 12,992 条，另有 13 条预检。重构 1,344 回合，其中 336 个为 oracle 诊断。主生成耗时累计 2,223.727 秒，训练查询补充 256.793 秒，合计 2,480.520 秒（约 41.34 分钟）；不含模型加载、哈希与审计。主实验最长单批 2.517 秒，补充最长 2.337 秒。模型参数更新数为 0。

全部主输出已封存，原生标签、提示词、输出解析、环境转换、旧在线回合和重复输入核验通过。旧在线对角线的 925 个决策与本轮一致；13 条预检原始响应也完全一致。首次审计在读取模型结果前因原生 tuple 与 JSON list 的表示差异失败；保留失败代码、计划和 `FIRST_AUDIT_FAILURE.json`，仅规范化这项比较后重新冻结审计器并通过。原始响应、生成代码和检查点未改写。

这些是同一 DEV、单种子、有限合成规范下的故障定位。四视图不是四个独立任务；交叉单元共享输入，不能按数千条独立样本计算置信度。当前结论是 **GPU 大批量 NO_GO；继续小规模共享模型修复**。完整目标未完成，尚无新方法收益、自然业务规范跨任务有效性或 32 步 Agent 协作证明。
