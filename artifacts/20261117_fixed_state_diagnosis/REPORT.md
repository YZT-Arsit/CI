# 固定状态审计：找到实际训练中的关系监督缺口

本轮先保持模型不变，将“关系判断是否正确”和“行动是否采用判断”分开检查。结论是：上一轮一致性模型确实退化为 Planner 固定选项策略；更重要的是，实际训练批次没有给 Planner 任何必须根据关系改选路线的监督。这个数据缺口已经定位，匹配修复对照已完成，补齐采样仍未解决问题；完整结果见[采样修复报告](../20261117_sampler_repair/REPORT.md)。

## 数据和边界

对上一轮两个冻结的 80 次更新检查点，枚举同一批世界中两个候选路线下的全部决策状态：280 个语义状态、每个两种呈现，共 560 条输入/模型。其中 Planner 112 条、Source 224 条、Worker 224 条。没有继续训练，全部自由生成的查询与行动先封存、后评分；最长一次生成 1.295 秒。

这是重复使用旧 DEV 的故障诊断，来自相同的两个任务实例，不能算新的泛化测试。与之前完整回合相比，这次两个模型会面对完全相同的后续状态，消除了“提前停止就遇不到困难状态”的偏差。

## 判断正确后，行动仍可能错

| 模型/角色 | 自己判断下的最优行动 | 注入正确判断后的最优行动 |
|---|---:|---:|
| 普通两视图监督 / Planner | 92/112 | 112/112 |
| 普通两视图监督 / Source | 224/224 | 224/224 |
| 普通两视图监督 / Worker | 119/224 | 152/224 |
| 条件一致性 / Planner | 72/112 | 72/112 |
| 条件一致性 / Source | 186/224 | 224/224 |
| 条件一致性 / Worker | 132/224 | 171/224 |

右列是明确使用真值判断的 **oracle 诊断**，不是模型自主能力成绩。它只用于判断：上游判断修正后，下游还有多少错误。

一致性模型的 Planner 在全部 112 条输入上输出 A。修正其中 51 条输入的错误判断后，它的行动一次也没变。普通监督 Planner 则在 44 条被修正的输入中改变了 23 次行动，修复了 20 次错误，没有引入新的最优性错误。相同提示的所有恒等对照均复现原始输出。

在一跳的 30 条**相同状态、两模型判断都正确**的输入上，普通监督模型 30 次选对，一致性模型只有 16 次选对。这避免了拿两个模型各自不同的“判断正确子集”直接比较。对 Worker，即使注入正确判断，普通监督仍有 72 次错误，一致性模型仍有 53 次错误，所以下游行动绑定也必须修复。

Source 的一致性模型在 128 个确实可完成的候选查询中只答对 48 个，普通监督为 92 个；它有 38 次在仍能完成任务时选择停止。与此同时，当前有限 Source 环境里“始终 Deliver”在全部 224 条输入上都是最优动作，因此 Source 高分本身不构成关系学习证据。Worker 的“始终 Full”在 224 条输入中有 120 次最优，普通监督的 119 次最优也不能单独说明它学会了规则。

## 可修复的采样缺口

重新核查上一轮**实际抽到的训练批次**，而非只看数据集是否包含样本，得到：

| 角色 | 状态出现次数（未重复计算第二种呈现） | 唯一最优动作 | 所有动作等值 |
|---|---:|---:|---:|
| Planner | 40 | 0 | 40 |
| Source | 40 | 34 | 6 |
| Worker | 80 | 50 | 0 |

Planner 的 20 批训练完全没有要求它根据反事实历史翻转最优路线。这是实际训练覆盖不足，不能只用“训练集里有反事实数据”来排除。进一步盘点发现：当前一跳 TRAIN 中，真正能让 Planner 两侧最优路线翻转的基础组只有 8 个，Meeting 与 Query 各 4 个。

针对这个缺口，[采样修复实验](../20261117_sampler_repair/PLAN.md)只替换 8 个 Planner 批次，覆盖全部 8 个严格反转组，保留 12 个等值批次和其余角色的所有批次。学习率、总步数、初始模型、损失与呈现随机种子均保持不变。它已在同一批新的 DEV 世界上比较“旧/修复采样 × 普通监督/一致性”四种情况。旧检查点复用，只训练两个新检查点。

干预结果否定了“仅补齐该缺口即可解决问题”的假设：一致性模型仍固定选 A，普通监督完整回合还出现下游退步。初始提出选 10 个不同反转组，预检发现仅有 8 个后即拒绝，未启动模型；最终使用 8 个真实组，没有伪造额外独立样本。

## 梯度诊断的限制

在三个冻结检查点、每个角色预先固定的两个 TRAIN 批次上，完成 18 次四分量梯度检查，均为有限数值，没有参数更新，最长 8.713 秒。方向既有冲突也有一致，不能据此宣称已经证明优化退化的原因。首个 Planner 等值批次在初始模型上，行动监督梯度范数约 0.00515，而行动一致性约 0.680；另一个批次的相对规模不同。这个局部现象与“缺少区分动作的监督”相容，但不替代采样干预实验。文献依据与边界见 [GRADIENT_SCOPE.md](GRADIENT_SCOPE.md)。

研究目标保持不变；仍为 **GPU 大批量 NO_GO**。这轮没有新增实际 Agent 协作或自然业务规范迁移证据，也没有把关系跳数当作协作步数。

另做了一个不涉及模型训练的数学检查：两个动作同样安全、同样能完成任务时，换用其中另一个并不降低任务价值，但完整动作分布一致性仍会惩罚这种变化。按已知训练价值分组后，该惩罚可以消失，同时保留安全与完成差异，以及非法输出概率。见 `VALUE_CLASS_CHECK.json`。这只是下一步可检验的修复候选，尚未证明它导致了当前失败，也没有证明采用该损失会改善模型。

采样规模模拟精确复现旧 80 批计划。原规则每个 Planner 批次有 4% 的概率抽到严格反转组，因此 80 次总更新（20 个 Planner 批次）完全漏采的概率为 44.20%。这只是采样覆盖概率，不是模型失败率预测；增加更新次数也不能增加仅有 8 个基础组的多样性。5 档规模各做 5,000 次模拟，精确公式与模拟值均保留在 `COVERAGE_SIMULATION.json`，没有模型训练。
