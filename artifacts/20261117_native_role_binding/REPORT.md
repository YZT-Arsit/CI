# 显式角色说明仍未使原生执行可靠

这次单任务跟进只替换通用系统说明，明确模型应扮演当前用户或客服，并把历史当作对话数据。模型、业务规则、工具、任务、预算、观察和历史内容保持不变；历史仍位于原用户消息中。**没有建立有效协作或任务成功。**

共发出 4 次模型请求。前 3 次形成并送达 3 条消息；第 4 次输出了合法 JSON，但把工具名放进 `kind`，没有遵循预先约定的工具命令结构：

```json
{"kind":"get_customer_by_phone","arguments":{"phone":"555-123-2002"}}
```

按冻结协议，它既不是允许的 `tool` 命令，也没有独立的 `name` 字段。执行器以 `invalid_command_format` 停止，保留原文，没有自动改写成工具调用。电话字段为原生公开合成任务数据。该意图不能计为实际成功执行。

重放通过：4 个原始响应、3 个实际命令、未执行的最终响应及其终止理由全部核验。最长请求 28.225 秒，低于预先声明的 40 秒上限；CPU 运行，用后卸载通过。补充完成审计在本次推理前已冻结：环境状态断言在初始化就通过，实际缺少要求的转人工调用，所以该状态断言不能当作任务成功。未宣称官方基准成绩或完整规范合规。

运行前的 `TREATMENT_CHECK.json` 核验了相同模型/任务/预算，以及与初次探针逐字相同的执行器、角色接口、审计器和观察快照。独立代码审查核验了最终冻结。最初“把整个历史搬到系统消息”的未运行草稿保留于 `prelaunch_revision/`；它因同时改变外来文本的指令位置而在推理前被放弃，模型调用为 0。

可继续使用的成果是：原生角色执行接口、自由生成协议失败的完整现场、状态断言的初始化反例，以及同时检查任务动作要求的独立审计。下一步应先把协议遵循和角色身份验证当作接口门槛，再评价任务效用与信息流；这不是已经完成的语言模型关系学习修复。**32 步有效协作、自然业务规范迁移及 GPU 大批量实验资格均未建立。**
