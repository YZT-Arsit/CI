# KCI-Align CPU pilot protocol

Run date: 2026-11-12 America/Los_Angeles. Start: 2026-11-13 03:23:21 UTC.
Time allocation: at most approximately 90 minutes. Each experimental subprocess or local model request has a 10-second ceiling; fast checks are not artificially delayed.

## Fixed objective

Learn recipient-knowledge-conditioned current disclosure and long-horizon compliant task completion with a shared role-conditioned execution model. CCE and DPR supply supervision. No new loss, research objective, or real-world CI truth is introduced in this pilot.

## Evidence classes

- Existing 29 PDFs: source-grounded literature, with explicit read coverage and page references.
- Existing and expanded deterministic worlds: synthetic software and mechanism checks only.
- NumPy preference learning: a small structured-feature CPU proxy, not LLM training or evidence of language generalization.
- Local Ollama: bounded real-model inference only if requests fit the time ceiling; timeout is an observed limitation, not a failed privacy answer.
- Real natural-language semantic validation, externally validated CI labels, LLM parameter training, GPU scaling, and broad-domain generalization remain unverified unless independently completed.

## Predeclared gates

1. All baseline behavior still justified by the fixed contract, plus regression cases for confirmed defects, must pass. A legacy test asserting an invalid statistical certificate must be revised transparently rather than preserved.
2. Unauthorized, uncommitted, unknown, or invalid data must never silently become a safe-success certificate.
3. Same-prefix preference pairs must match authorized prompt, actor, environment/norm/oracle/reference versions, horizon, and budget.
4. Known CI violations imply safe-success=false even if terminal task utility is not known. Unknown semantic or normative facts remain unknown.
5. Statistical diagnostics do not prove equality of higher-priority objectives. Cost significance alone cannot certify a lexicographic preference.
6. Candidate undercoverage or search exhaustion is not infeasibility; witness cost is not optimal cost.
7. All synthetic records carry provenance, grouping, evidence, and versions. Near-duplicate/counterfactual variants of a world cannot cross splits. A single relation family cannot establish rule-family generalization.
8. Learning ablations must expose duplicate source memberships, imbalance, observable-label conflicts, and baseline information budgets. No claim of independent DPR benefit if its pairs duplicate CI/future pairs.
9. Bulk LLM training is NO-GO without reliable semantic/norm labels, replayable environments, useful verified preference coverage, and a validated training/evaluation adapter. Passing synthetic checks alone is insufficient.

## Planned short experiments

| Factor | Controlled intervention | Check / falsifier |
|---|---|---|
| Knowledge | Local background, delivered ledger, authorized shared ledger | Same observable facts imply the same modeled closure; protected join is detected |
| Context | Allow/deny derived relation, renamed entities, similar identifiers | Legal combinations allowed; unrelated keys do not join |
| Delivery | Draft, duplicate delivery, reordered history | Drafts do not update knowledge; duplication does not create extra facts |
| Length | Unrelated histories of 0/4/16/64/256 messages | Irrelevant history does not change CI label; measure cost growth |
| Horizon | Short and sufficient task deadlines | Feasibility reflects deadline, with bounded scope explicitly reported |
| Costs | Unit and heterogeneous action costs | Consistent cache and exact comparison; objective remains unchanged |
| Search | Node/action caps, incomplete candidates, unknown body | Evidence downgrades correctly; no false negatives from misses |
| Reference | History-aware, history-blind, conservative, abstaining policies | Separate true reachability from reference execution failure |
| Statistics | Rare violations, null effects, unknown outcomes, small n | No certified cost preference from unproved risk equivalence |
| Data | Missing fields, conflicting observations, duplicate sources, grouped splits | Fail closed or explicitly flag unsupported training rows |
| Learning proxy | CI/future/repair subsets, imbalance, label noise, ordering | Report held-out synthetic diagnostics without promoting proxy to LLM evidence |
| Runtime | Local model latency, malformed outputs, token truncation | Preserve raw responses/status and exact model/request versions |

## Stop rules

Do not launch GPU training, external paid models, large downloads, or unrelated processes. Preserve negative and timeout outcomes. Stop before the time allocation is exhausted and reserve time for a self-contained Chinese report with data/results and a bulk-experiment readiness decision.

## Amendments after independent data audit (03:45 UTC)

The proposed held-out proxy evaluation is cancelled: 48 surface renderings collapse to one underlying eligible-yes base template and one relation family. Name substitutions must not cross a purported independent split. Primary validation/test groups are empty; all NumPy results are same-corpus pipeline diagnostics. The 38 canonical preference patterns are not 38 independent tasks. Raw and deduplicated records retain source memberships so repair overlap cannot be mistaken for new supervision.

Exploratory initialization diagnosis adds verified-trajectory SFT followed by a separately frozen DPO reference. This remains a finite linear policy, not LLM training. A controlled training-order follow-up uses exactly the same CI and future minibatch multisets in both staged orders and mixed order. Beta and noisy-label sweeps are sensitivity checks, not tuned method comparisons. The supplied-cost Ollama question is only a static arithmetic/selection sanity check; actual menu-constrained agent rollouts are reported separately.

## CPU preprocessing and optimization extension (04:07 UTC)

Before bulk training, tokenizer and optimization invariants can be checked without a GPU. The extension uses only official tokenizer assets (fixed revision and hashes; no model weights) in isolated dependencies, and NumPy diagnostics on the existing finite DPO design matrix. Every experimental worker retains the at-most-10-second ceiling. It does not change core environment, data labels, scientific objectives, or training loss.

Tokenizer checks cover actual chat boundaries, equal prompt prefixes, completion-only labels including EOS, both padding sides, batching, position IDs, and rejection of context/completion truncation. Synthetic log-probability bookkeeping must not be represented as a real-model forward result. Sum-versus-mean is a diagnostic counterexample, not a new objective proposal.

Optimization checks cover sample-count-weighted accumulation, uneven simulated ranks, clipping order, complete optimizer/RNG restoration, frozen reference state, stable finite-precision arithmetic, and shared role-gradient summation. Incorrect control implementations are deliberately compared to the declared mathematical objective; they are not claims that an unimplemented trainer currently contains those bugs. Actual model kernels, distributed frameworks, mixed precision and task generalization remain unverified.
