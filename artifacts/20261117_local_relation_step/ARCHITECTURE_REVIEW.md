# 先验证推理接口，再增加全局训练

研究目标仍是Proposal v0.6的共享执行语言模型：利用可信接收者知识与任务依赖，自主选择合规且有效的行动。不能把一个外部闭包程序的答案送给模型，再宣布执行模型学会了关系。

本轮开始时，上一轮已构成真实进展：名称覆盖修复已实现、144次训练及256自主回合已完成并上传。然而它的完整门槛失败：一跳四呈现0/8→8/8，总成功49/128→74/128，违规15/128→27/128；三套名称下的TRAIN变化配对均下降。更早的采样、优化、行动输入和答案位权重试验也没有联合解决问题。因此继续做相邻损失微调不是已有证据支持的唯一方向。

当前接口要求模型直接从整段事实与计划输出“这个动作之后还可否合规完成”。这个答案同时需要实体绑定、方向性、关系组合、授权条件和任务依赖。某个最终0/1错误不能区分哪一步失败。此前trace模型已经训练过完整PATH文本，但没有逐步核验实际生成的局部推导。因此本轮先拆出一步关系扩展，避免把“多写一段解释”当成机制修复。

依据经Exa定位的原始论文[ProofWriter](https://aclanthology.org/2021.findings-acl.317.pdf)第3.6和6.1节，生成完整证明与反复生成一步推论是不同设计；迭代设计需要将模型生成的结论继续作为输入，也会积累错误并增加计算。这里仅借鉴设计区分，没有下载它的数据、复现其结果或宣称新颖性。

执行顺序与解释边界：

1. 冻结现有两个模型，测试零样例与四个固定TRAIN样例下的一步扩展。新提示格式失败只能说明该接口下的表现，不能证明神经模型没有能力。
2. 若这一必要条件未过，再单独登记局部监督学习，使用新生成的确认组；保留冻结探针结果。若条件已过，才值得把模型自己的推导接回多步判断与动作。
3. 未来闭环必须保留模型每一步预测及错误，不能用正确前沿、真值闭包、动作过滤或规则兜底替换失败。显式循环结构要作为系统先验披露，不能包装成模型自行发现算法。
4. 推理轮数与Agent交互步数分别计数；一步或32轮内部推理均不证明32步Agent协作。自然业务规范、UNKNOWN处理与跨任务有效性仍需外部验证。

本轮的标签程序是评估真值，不是运行时执行策略。必要门槛的通过不等于完成目标；失败也不证明方向无效。完整目标继续保持，GPU大批量仍为NO_GO。
