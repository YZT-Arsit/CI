# 关系判断到行动：定位别名错误与选项绑定错误

本轮延续原研究目标，优先修复语言模型如何把关系判断用于行动。旧归档保持不变。所有模型实验均为 CPU 上的 SmolLM2-135M LoRA；不把合成诊断、原生环境检查或单种子训练当作完整研究结论。

## 已确定的故障位置

将之前一起变化的四个因素拆开：实体名字、已接收事实的顺序、计划顺序、行动选项顺序。在原来 16 对历史反事实世界上完整交叉 16 种呈现，总计 512 个世界呈现。语义图保持一致，192 个旧输入与原始输出均精确复现。

| 单独改变的因素 | 查询估计改变 | 行动改变 | 估计不变时仍改变行动 |
|---|---:|---:|---:|
| 实体名字 | 40/512 | 32/256 | 0 |
| 事实顺序 | 4/448 | 2/224 | 0 |
| 计划顺序 | 4/288 | 2/144 | 0 |
| 选项顺序 | 0；512 次输入相同对照 | 8/96 | 8 |

分母只包含实际改变相应输入的比较，避免把随机排列恰好不变算成有效干预。比较重复使用同一组世界，不能当作数百个独立任务。完整 16 种呈现下，只有 10/16 世界对始终选对；26/32 个单独世界始终选对。

因此至少有两个不同问题：名字变化会破坏上游关系估计；即使自身估计完全相同，选项字母变化仍会破坏下游行动绑定。

进一步将每个世界在基准呈现下的**模型自身估计**固定，再改变全部呈现，稳健配对成功从 10/16 变为 15/16，单世界从 26/32 变为 31/32。这是同一 DEV 集上的中介干预诊断，使用的估计也不是全部正确；不能将 15/16 当成新训练模型的泛化成绩。它支持先修复查询稳定性，同时单独检查选项绑定。

## 避免增加无必要的监督分支

另一项有限审计检查：是否仅预测“合规完成仍有可能”就丢掉了行动安全性。在现有 5,760 个 TRAIN 状态、13,824 个候选行动中，保留角色和规范化行动身份后，没有发现相同完成位对应不同安全/价值标签；相同整组完成位的状态，也都至少有一个共同最优行动。

因此，当前语料不支持“必须新增一个安全预测头才能解决问题”的说法。此检查只覆盖现有有限训练分布，不能推出自然业务规范也可以如此压缩；模型当前仍可能预测错已有信号。

## 对照修复

两组从同一初始检查点出发，使用完全相同的 80 批数据、角色比例、两种随机呈现和优化器设置：

- 对照组：两种呈现的监督学习。
- 修复组：在上述训练上增加语义对齐的一致性损失。查询按同一个世界、同一个行动对齐；行动先还原选项字母对应的语义。只有两个视图的模型自身估计完全一致时，才约束行动一致，防止强迫模型忽略不同证据。

所有概率质量都保留，包含非法输出的 OTHER 概率；双侧梯度均存在。不同历史反事实不被强行对齐。实现与身份对照、真实模型梯度检查均通过。它是一项修复基线，没有建立新方法贡献。

评估含 36 个基础组、56 个语义世界、112 个呈现版本/模型；随机世界未训练过，但仍来自相同的两个任务实例，因此不是来源级留出。两组共 160 次参数更新，单次最长 5.482 秒。没有非法格式输出。

| 检查 | 两视图监督对照 | 增加条件一致性 |
|---|---:|---:|
| 一跳：两个历史 × 两个呈现均完整成功 | 8/8 对 | 0/8 对 |
| 三跳：上述四个回合均成功 | 0/4 对 | 0/4 对 |
| 内部边反转：上述四个回合均成功 | 0/4 对 | 0/4 对 |
| 环形关系：上述四个回合均成功 | 0/4 对 | 0/4 对 |
| 可选发布：两个呈现均成功 | 0/4 | 4/4 |
| 明确授权：两个呈现均成功 | 4/4 | 4/4 |
| 未送达的历史：两个呈现均成功 | 4/4 | 1/4 |
| 两条路径均不合规：两个呈现都保持安全 | 0/4 | 3/4 |

对无合规完成路径的条件应看安全保留，不能要求不可能的任务成功。全部呈现混合后的描述性计数：监督对照完整成功 75/112、保持安全 76/112；一致性组完整成功 34/112、保持安全 98/112。安全但任务失败从 1 增至 64 个呈现回合；Source 的 WITHHOLD 从 0 次增至 41 次。两组到达的后续状态不同，这些行为次数不能当作匹配状态下的因果效应。

**结论：本次条件一致性配置失败，不能作为安全—效用同时改进的方案。** 它修复了部分可选发布情形，却严重损害必要任务完成；连一跳配对成功也没有保住。对照组的一跳表现可保留为有限进展，但尚未解决组合泛化和安全条件。单种子结果也不足以否定所有一致性方法。独立重放的输入、查询、行动和状态均核验通过，详见 `repair/AUDIT.json`、`repair/VIEW_AUDIT.json` 与 `repair/BEHAVIOR_SUMMARY.json`。

下一步应先用同一批固定状态，将查询错误、忽略自身正确估计、过度停止分别计数，并在开发集上检查各项训练梯度是否冲突，再选择局部修复。暂不扩大一致性训练，也不凭更高安全率宣称解决问题。不能把这个失败归结为“135M 模型一定不行”而跳过监督和优化诊断。

## 原生协作环境的进展

已建立角色各自可见的原生工具会话，并在 114 个公开任务上验证工具结果隔离、错误角色调用拒绝、消息送达/丢弃与原始计划执行。详见[角色接口报告](../20261117_native_roles/REPORT.md)。其中模型决策数为 **0**，所以既不是自主协作成绩，也不是 32 步协作证明。

## 当前结论边界

本轮定位了可复现的关系估计错误与行动绑定错误，并留下匹配训练对照。大规模 GPU 实验仍为 **NO_GO**。完整目标还需要：稳定且正确的关系到行动学习、独立来源和多种子验证、真实多角色决策与消息依赖，以及自然业务规范的有效性和跨任务检验。

本轮及角色接口共 55 个 JSONL 文件已无损压缩，包含原始模型输出、训练轨迹和原生执行记录。全新目录恢复 55/55，重复恢复不修改文件，遇到不同的既有证据会拒绝覆盖；见 `ARCHIVE_VERIFIED.json`。两个新增 LoRA 检查点均保留。[复核说明](REPRODUCE.md)提供数据、实现和运行入口。
