# Separate renaming from ordering on selected TRAIN prompts

The previous selected-fit probe changed names and edge/frontier order together. It did not identify which change produced degradation. Freeze a2×2presentation diagnosis while the rehearsal worker executes and before scoring its outputs. This adds no updates and cannot change primary gates.

Use exactly the16seen prompts selected for each schedule by the prior fit probe: six switch pairs and four controls from the last epoch. Conditions are seen, names_only, order_only and both. Names come from the same TRAIN pool. For each selected pair/control choose deterministic new seeds from490000000+schedule*1000+selection_index*10 upward, checking only that all12entity names differ and the edge ordering changes. Selection never reads predictions or correctness. Both sides of each pair share seeds; control examples may share seeds. The original seed reconstructs every original prompt byte-for-byte. Freeze actual permutations and mappings through deterministic regeneration, not string replacements on substrings.

Initial checkpoint evaluates all three panels (192responses). Each of three local-only and three replay checkpoints evaluates its corresponding64responses. Total576newresponses, no reuse counted, zero updates. For each checkpoint/panel/condition report correct/16, both-correct/6, controls/4, invalid and false-positive/negative counts. Verify answer invariance, prompt identity, fact multisets/order and tokenizer lengths. New names and order must not change any semantic edge, initial node or target. Use the same CPUFP32/four threads and greedy16token decoding as the main study.

This is a TRAIN-presentation sensitivity diagnosis with correlated templates, not held-out task generalization. Differences between conditions identify finite presentation effects for these frozen models/panels; they do not establish a unique internal mechanism or universal invariance. Even a perfect result cannot replace the full operator/action gate, autonomous execution, natural-norm validity or32step collaboration.
