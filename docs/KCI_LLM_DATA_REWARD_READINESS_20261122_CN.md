# KCI-Align: 4B 放大前的数据与奖励审计（2026-11-22）

审查来源：当前 A→R→B→C 原生动态链、2026-11-21 CPU 训练检查点、原始研究计划 Reward–Data 合同。仅执行只读数据审计与额外 CPU 对照；未新增 GPU 训练，未修改既有环境。

## 审查结论

**CPU 训练机制能运行且在当前任务上可重复；不能推断 4B 数据已稳定。需要小规模、有目的的数据扩充和奖励偏好生成修复。最重要的是修正单标量奖励与 CI-first 研究目标的不一致。**

## 1. 数据真实独立性与覆盖缺口

| 分割 | 独立任务根 | 派生世界 | 图机制 |
|---|---:|---:|---|
| TRAIN | 4 | 16 | quorum2of3, quorum3of5, unequal_or, cascade3 |
| DEV | 1 | 4 | parallel_join |
| Developer-seen TEST | 2 | 8 | asymmetric_paths, staged_bridge |

总计7个图根、28个世界。每个根只是 matched/tradeoff × PACKAGE_A/B 交换，共4个强相关派生状态。共有calendar、retail、document三类模拟业务。最新动态链中显式授权例外为**0/28**，虽然旧V3.1版本另有authorized_related，但没有进入当前A→R→B→C训练。

当前B/C/A链仍为固定动作协议、公开Horn关系、S01–S06结构化事实，CPU前向有显式规则传播，并非4B在开放文本中自主提取、组合CI事实的证据。此前真实Qwen3-4B运行在旧Meeting/Query任务，不能直接当作新链的泛化结果。

当前三阶段CPU训练用28条来自模拟器同状态转移的违规RAW/合法VERIFY纠正对（不是全部来自真实模型失败轨迹）、B阶段32个合法OPEN/SKIP候选与各K=4实际续行、A阶段16个合法证据包候选与各K=4续行（其中11/16被接受）。每模型seed用于B/A教师的完整续行共384条。

## 2. 奖励定义与研究目标有实证冲突

原Proposal中的轨迹判定为 J=(CICompliant,TaskSuccess,-ExecutionCost)，优先级 CI 合规→任务成功→合规完成路径成本。

现有原生 reward：安全成功为 1-cost_per_step*steps，违规=-1，安全未完成=0。已核对28个世界的原生可达终局，成功奖励最低为0.202，没有出现成功收益负值。

但在随机策略下，最大化单一期望标量不等于CI优先的序贯目标。实际保存CPU actor的复现例：
- 世界 DG01_M01__tradeoff__swap0，冻结下游策略seed7；
- 上游PACKAGE_A：平均标量0.669606，安全完成率0.986765，未来违规率0.0132353；
- 上游PACKAGE_B：平均标量0.663999，安全完成率约1，未来违规率约0；
- 单标量会给A正向偏好，但它的隐私风险更高且成功率更低。

三种子实际K=4有限续行中均将该场景A标为偏好，样本均值差+0.028、一致率100%；因为1.32%的未来违规非常容易在4次续行中漏检。这不是计算错误，而是训练标签确实与CI优先目标不一致。

审计四种保存策略、三个种子、28个世界，2,832个合法双动作比较（高度相关）：
- B已修正及全角色训练时，A_SEND 84个模型-世界比较中12个与CI优先规范排序冲突，集中在DG01（train）和DG19（developer-seen test）两个根；
- preflight 168个双合法动作比较未发现同类冲突；
- release 456个双合法RAW/VERIFY比较中20个存在任务成功率略低但标量因较低成本更高的冲突；
- 违规惩罚由-1提高至-4可在当前CPU数据上消除A的12个冲突，但20个任务成功-成本冲突仍存在，所以仅靠调惩罚无法表达三层目标。

风险差和任务成功率使用当前原生状态树的精确冻结策略期望，并以1e-3差值阈值作诊断；不是对所有真实世界不确定性作统计保证。

## 3. 现有纠错训练过度压制了合规披露

当前训练世界中下游来源角色的RAW、VERIFY同时合法的状态有76个；其中72个经冻结策略反事实价值检查，RAW合法、省成本，并且在该检查下不降低安全任务成功率。现有下游DPR使用28条违规RAW→合法VERIFY负例，没有独立合法RAW正例。

三个种子 CPU R-only训练对照：
| 探索TEST指标 | 只用28条违规纠正 | 28条纠正+72条合法RAW正例 |
|---|---:|---:|
| P(选择立即合法RAW) | 7.03% | 39.70% |
| 完整随机策略期望回报 | 0.5321 | 0.5462 |
| 随机策略CI违规率 | 约5.06% | 约5.12% |
| 贪心安全完成 | 各seed8/8 | 各seed8/8 |

增加合法披露正例改善效用与披露校准，但平均泄漏风险轻微增加；不能宣称无代价地同时提升隐私和效用。实验验证了现有数据不平衡对训练行为的真实影响。

## 4. 应如何定向扩充数据

不应该将已有28个派生世界改写几千条文本后即宣称得到更多独立任务机制。

第一批工程建议扩充**12–20个新独立CI工作流根**（不是新 fact label、包名和cost variants），并在不同业务目的、授权/不授权、接收者权限、真实交付历史、角色接力数和实际任务约束上变化。每根保留少量严格匹配对，形成可以分离历史、许可、任务完成与纯成本差异的因果对照。按独立任务根留出未参加开发调参的新测试根。

三类数据必须对应算法监督：
- D_CI：直接违规、组合推断违规、合法原文/选择性披露、明确授权例外、合法关联与无关历史。
- D_future：两个立即合法行动导致不同的未来CI风险、任务完成、必要信息与成本；单独保留纯成本对照，不把全部未来偏好当作CI收益。
- D_repair：真实on-policy失败轨迹中在实际下游决策位置的可执行纠错，并保留上游合法披露的因果归因。
同原生语义另外建立自然语言视图（工具文本、接收账本、任务目的和规范的不同表述），作为4B输入鲁棒性评测；文案改写不算独立新机制。

## 5. Reward–Data修复方案

训练偏好生成不要只由mean terminal scalar reward排序。保留原始外部标量供RL和监测，但CCE偏好教师要输出多目标结构：
   immediate CI verdict; downstream verified CI risk;
   CI-safe task success; conditional successful execution cost;
   number of rollouts; state hash; verifier reason; uncertainty status。

偏好选择顺序：
1. 真实立即CI违规则严格劣于合规且任务可行的动作；UNKNOWN不作为硬标签。
2. 对两个立即合法动作比较可验证的未来CI风险；若小K样本无法排除罕见违规，不能声称成本更优就等于总体更优。
3. 在合规风险可比较时优先合规任务完成和必要信息充分性。
4. 最后才比较完成路径成本。
5. DPR只改实际违规/无效动作所在角色，不把合法上游动作当错。

不建议立即将所有违规penalty机械提高到某个数字然后上4B；这会改变训练目标且仍解决不了成功率/成本错位。对于1.3%的未来风险，即使K=4全部没看到违规也根本不足以证明其不存在，因此要结合已有CI verifier、规则闭包证据及适应性样本预算；证据不足的候选返回UNCERTAIN而不是强行给DPO标签。

## 6. 4B下一步

现有数据**可以用于4B端到端工程smoke test**：动作接口、角色LoRA路由、可见观测、轨迹哈希、实际梯度和token预算。但不应把28个派生世界用作4B论文主训练/主测试。

优先次序：先修正偏好生成的Reward–Data合同，重用已存在的72个合法RAW正例并补显式授权场景；同时定向扩充独立任务机制，再做4B有限预算阶段训练。评价明确分开CI违规、合法业务成功、长期Regret、合规行动充分性和采样成本，不再只报告加权总回报。
