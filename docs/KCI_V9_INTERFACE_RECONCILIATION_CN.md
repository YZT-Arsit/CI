## 模型输入、动作与奖励

| 阶段 | 模型可见输入与动作 | 执行器如何计分 |
|---|---|---|
| 协商首步 | A 看到公开库存、己方估值、预约分、固定规范和两个可签草案。对手的真实估值只在授权调解角色中可见。 | 实际发布草案产生 A 的签名回执，以接受不等式缩小公共收件人的可行估值集。 |
| 协商续行 | 同一模型扮演私有调解员，看到双方授权估值、实际草案和已发生的事件。菜单包含满足该事件且双方可接受的分配及安全中止。 | 执行签名最终分配后再更新收件知识。按库存、双方效用和事件判断任务成功；按受保护估值性质是否被新唯一确定判断推断违规。中止没有最终公开回执。每个首动作精确汇总七个等概率事件。 |
| ProofWriter 首步与续行 | 源 A 看到本地记录、公开规则、规范、已交付历史及授权的 B 候选目录。源 B 使用自己的记录、公开任务／规则与交付历史。两个源角色共享权重。 | 使用原生 Env.deliver 记录真实签名交付。只对成功交付的文字做规则闭包。Env.final 用收件证明核实两个任务槽，现有协调器确定性提交。失败交付不增加知识。记录直接违规与新增推断违规。 |

语义动作以规范 JSON 编码。训练接口与执行接口在同一展示条件下生成相同的文字和动作，交换标签不会改变模型输入。共享模型对每个动作完整回复及 EOS 的对数概率求和，屏蔽提示 token，选最高分动作。该规则可能偏好短动作；协商中止的原因尚未单独识别。调解员续行与 B 的输入是此次对接时明确构造的角色界面，未来比较应保持相同的工具权限和菜单。[分层加载和目标](../code/kci/v9_interface.py) · [原生执行](../code/kci/v9_execution.py) · [共享模型计分](../code/kci/v9_policy.py)

## 训练调用

V9 即时 CI 按语义对或有掩码的动作集合加载。业务就绪与终局监督保留各自用途。静态证据选择走逐项 BCE。494 条 HOLD 仅供对照；242 条成本／随机参考诊断只允许诊断访问。141 条 DPR 属于先前模型失败来源，其中 138 条做过语义动作重建；此次新采集的失败另存。多源核心须指定单一分层和 reference_distillation，DPO 的冻结分母是同一展示下的基线动作概率。交付参考续行、当前模型实际续行与 DPO 基线分开保存。

```python
d = Deliveries(v9_path, core_path)
pw = d.core_reference("proofwriter_local_attestation", purpose="reference_distillation")
ci = d.load_tier("IMMEDIATE_CI_ORIGINAL_ACL", purpose="training", objective="masked_action_set")
loss = d.loss(pw[0], purpose="reference_distillation", seed=7, view=0,
              score=current_semantic_logps, baseline=frozen_semantic_logps)
```

回调接收渲染后的提示和按展示顺序排列的语义动作。动作对使用完整回复概率，有掩码集合只在标出的正负动作上归一化。静态证据回调接收按展示顺序排列的条目 ID，返回同序纳入 logits。数据交付的采样权重只用于诊断。目标路由、梯度与禁用分层已有测试。[接口测试](../code/tests/test_v9_interface.py)
