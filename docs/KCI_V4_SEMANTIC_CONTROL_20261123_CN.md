## 2. V4 原始标签、数据规模与两种视图

V4 原始共有36条 TRAIN 正常/换位记录、18组独立同状态偏好；本轮只用其中 SourceAgent release 的 **18条原始记录 / 9组独立比较 / 3个训练根 DG31/32/33**。三根各有1个 `D_CI` 危险侧比较、1个 `D_positive_RAW` 合法侧比较、1个 `D_authorized_positive_RAW` 授权正例比较；保留真实角色（ComplianceAgent、RecordsAgent）、阶段、法定动作及 signed tool output。

`TRAIN_HISTORY_AWARE.jsonl` 教师分布为 **VERIFY 3、RAW 6**；`TRAIN_HISTORY_BLIND.jsonl` 教师分布为 **RAW 9**。这两臂对每个训练状态共享逐字节完全相同的角色可见真实历史、任务、规则、授权、候选动作；只改变教师标签。历史盲标签已在原生训练根重放：仅在教师状态的克隆中清空收件人R的 `delivered` 和 `ledger`，**9/9** RAW均为 VALID 且安全完成，并比VERIFY少1个实际步骤；没有任意篡改标签，也没有把盲标签当真实历史监督。

位置无关动作接口 `tools/kci_v4_semantic_action.py` 沿用先前 `kci_shared_semantic_action.py` 的原生语义动作评分方式：将 V4 actor-visible 文本去除**仅有**的任意字母选项菜单，替换为排序后的原生语义动作列表；为每个候选 `a` 构造完全相同的评价问题，通过
`eθ(o,a)=logPθ(ACCEPT|o,a)−logPθ(REJECT|o,a)` 计算分数，再取 `softmax_a eθ(o,a)`。此处 ACCEPT/REJECT 的 A/B 是**固定评分含义的两个输出 token**，不是随 `option_order` 变化的候选动作位置。换位后的每个候选 `a` 得到字节完全相同的输入，训练时只算一次，不把换位复制当独立数据。三动作 RAW/VERIFY/ABORT 仍同时评分。

开发根为DG34和DG35，分别5个有效原生状态（`risky/safe/hold/authorized/equivalent_order`），共10个状态。每个开发状态又使用 **两种已由原始 V4 源提供的角色文本视图**：
1. `native`：原始真实收件历史与工作流/实体名字；
2. `entity_alias`：仅将 case/workflow 名称换为匿名别名，所有事实、角色、规范、工具权限、规则与原生行为判定不变。

每一种文本视图的菜单换位输入也逐字节一致；无须重复运行模型计入样本。开发指标一律按**两个独立根**计数，不把两个视图×两个菜单顺序当作8个新根。

**DG36 继续封存**，在本轮 V4 原始文件读取环节于 JSON 反序列化之前排除最终测试行；未读其状态或标签、未预测、未调参、未按其结果选模型。新生成的 TRAIN/DEV 文件中不存在DG36。V4数据目录只读，原生规范/verifier未修改。

## 3. 冻结模型、训练目标和真实计算预算

Qwen3-4B-Instruct-2507-ms，NF4量化、BF16、一个共享LoRA `r=8, alpha=16`，target modules `q_proj/v_proj`，AdamW，学习率 `2e−5`，seed7，`max_prompt_tokens=4096`，gradient checkpointing，**每个训练臂正好96次优化更新**。每次更新从9组独立比较中选1组，以固定采样序列训练；实际采样序列SHA256一致，所有模型从相同冻结预训练底座和seed7的新LoRA初始化，不使用角色专属权重切换。

- **历史感知 CE**：对 V4 真正的同状态安全/任务成本偏好，最小化正确原生动作的语义 softmax 负对数似然。
- **历史感知 DPO**：对相同 `chosen_action/rejected_action` 及固定预训练参考分布使用 DPO，`beta=2`；参考模型不是旧R-LoRA、更不是有限环境Q*或4B的Qπ。由语义动作 `logπθ(a+|o)−logπθ(a−|o)` 减去冻结参考同状态差构造。
- **历史盲 CE**：同一输入、同一更新序列与超参数，唯一变化是教师从原生历史不可见克隆状态导出，9/9训练标签是RAW。
- **冻结对照**：原始预训练底座、之前另行训练128步/204对的R-LoRA均只推理不更新；旧R-LoRA不是同预算新方法，不当作等预算优化器结果。

| 实验 | 优化更新 | 可微候选动作前向/反向调用 | 额外冻结参考前向 | GPU真实训练耗时 |

| 历史感知 CE | 96 | 288 | 0 | 133.82秒 |
| 历史感知 DPO | 96 | 288 | 27 | 131.99秒 |

## 5. 真实全链 Agent 轨迹：两种不可混淆的协议

使用 V4 原生 `V4ChainEnv`，执行真实 `env.transition`，追踪业务结果、接收者R的已送达ledger和知识闭包、实际步骤与原生 verdict。只读 V4 执行器源码按字节复制到 `code/kci/data_v4_env.py` 供主项目复用；原始V4项目本身没有改动。

### 协议一：受控披露，真实端到端原生执行

预先按 V4 实际验证过的源Agent和Coordinator前缀达到目标第一次release；之后每个release由同一4B策略决定，其他读取/证明发送/业务最终提交由跨方法相同的确定性原生执行器完成。相同root/条件真实初始收件历史不变。

每个方法在2个新根×5种条件×2文本视图运行20个完整原生团队轨迹，共 **60条**：

| 策略 | Native视图合规完成 / 违规 | Alias视图合规完成 / 违规 | 每视图模型披露决策数 |
|---|---:|---:|---:|
| 感知CE | 8/10 完成，2/10 违规 | 8/10 完成，2/10 违规 | 18 |
| 感知DPO | 10/10 完成，0/10 违规 | 10/10 完成，0/10 违规 | 20 |
| 历史盲CE | 8/10 完成，2/10 违规 | 8/10 完成，2/10 违规 | 18 |

此协议**不是纯自由生成完整LLM团队**，非披露角色决策被固定，真正验证的是本轮语义披露策略进入多角色任务链后的实际原生后果。它验证了单步的风险/成本效果，却不能被称为算法对完整 Qπ 的学习收益。

### 协议二：同一共享4B适配器完全参与各角色行动

从真实初始状态出发，同一模型对各角色的合法原生动作菜单逐项评分，不切换任何角色专属LoRA。每个方法在DG34/35的10个配置各运行1次，共 **30条自主团队轨迹**，不强制上游发送原指定package，因此这些配置**不再是匹配历史的严格反事实对**。

| 策略 | 合规完成 | 中止 | 原生UNKNOWN/拒绝执行而未完成 | CI违规 |
|---|---:|---:|---:|---:|
| 感知CE | **3/10** | **5/10** | **2/10** | 0/10 |
| 感知DPO | **5/10** | **5/10** | 0/10 | 0/10 |
| 盲CE | **7/10** | **3/10** | 0/10 | 0/10 |

感知CE存在两次模型过早调用 `COMMIT_RESULT`，原生verifier返回 `UNKNOWN` 且状态哈希不变；本轮记录为**无效行动/未完成**，没有覆盖verifier、没有重放成功后缀替换失败。其它模型的失败以中止为主。自主协议0次CI违规包含大量过早退出及不同于原始风险状态的上游行为，不能得出共享策略已经保障CI的结论。模型分别作出66、80、86次实际自主动作选择。

整轮共 **90条原生团队轨迹**，有各动作前后状态哈希、原生验证结果、R知识变化、模型动作概率、角色和完整terminal存档（`native_agent_3arms_v2/FULL_NATIVE_TEAM_EPISODES.jsonl`）。真实原生团队运行78.34秒，累计候选动作推理前向调用数为CE265、DPO315、盲CE327（包括60条受控轨迹）。RTX 4090 D运行结束后空闲；未伪造峰值显存。

### 避免的错误结论

- 不能只根据 DPO控制团队的10/10合规任务完成宣称已学会历史，因为实际是始终VERIFY并产生过度成本。
- 不能因为 CE/盲CE的Hold 2/2宣称学会Hold，因为它们本质上是“始终RAW”多数类捷径，在危险侧同样泄漏。
- 不能将自主团队0/10违规当安全对齐成功，因为大量中止、UNKNOWN以及自主上游选择造成的场景漂移。
- 不能将 native 固定后继的任务结果叫做当前策略Qπ，也不能将 finite native Q* 直接用于模仿当前4B Qπ。
- 不能因为位置/实体别名不变就认定模型完成了公开Horn规则的接收者知识状态推理。

## 6. 失败原因与下一步门槛

**本轮主要失败直接证据是“学习目标在少量独立训练根上选择了固定动作捷径”，而非单纯选项位置问题。**

已确认：位置无关语义动作接口消除了原来的菜单字母位置捷径；在此接口下CE仍选恒RAW、DPO选恒VERIFY，历史盲CE也选恒RAW。说明当前仅9组独立同状态比较（危险VERIFY3、合法/授权RAW6）及对应优化配方，**尚不能建立有效的知识条件判别**。但不能据此直接判断为“V4数据标签错误”——原生训练历史盲反事实9/9可复算，真实历史感知标签含即时违规和两个安全成功后缀，方向可靠。训练根都未拟合，跨根泛化问题和模型容量问题不能单独归因。

数据/泛化限制：只有3个训练独立业务×规则根、2个开发根，单随机种子。DG34的OrderAgent并非本轮release训练角色，两个开发根图结构也是新类型；这些仍是有意义的覆盖风险，但本轮并没有满足“训练先成功、只在新根失败”的判别前提。

**下一门槛只围绕可学习性和监督设计，不提前升级RL**：保留V4原生标签和数据拆分，检查三个独立根的历史敏感梯度/监督权重与合法RAW负例对称性、候选动作A/B评分器的校准与类别捷径；仅当明确的训练 Flip、合法RAW和违规RAW均可学且两种文本视图稳定，再考虑冻结同一下游4B团队跑A/B真实策略续行，最后才建立CCE/DPR相对简单Action CE的真实长期增量实验。**DG36继续封存**，不对其调参、选方法或反复评价。
